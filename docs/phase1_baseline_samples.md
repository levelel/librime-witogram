# Witogram 第一阶段观察样例集

## 1. 定位说明

本文档从主测试语料 [test_sentence.txt](file:///c:/Code/outwit/witset-worker/tests/test_sentence.txt) 中抽取了一批典型观察样例。

这一批样例的目标不是承担正式验证职责，而是帮助开发阶段更快观察最容易暴露问题的场景：

- 高频同音干扰
- 长句上下文依赖
- 文学表达中的低频词
- 容易被单字高频带偏的词组

注意：

1. **正式验证以全量 `test_sentence.txt` 为准**
2. 本文档中的样例**不能替代全量测试**
3. 它只用于人工观察和问题定位

---

## 2. 使用原则

这组样例主要服务于以下三件事：

1. 判断某次改动是否真的让排序更合理；
2. 判断某次改动是否只是“换了一种错误”；
3. 判断当前错误主要来自：
   - 字典权重
   - 语言模型分数
   - 两者融合方式

这组样例优先观察：

- Top-1 候选是否合理
- Top-3 中是否包含明显应优先的候选
- `Dict / LmRaw / LmScaled / Base / Total` 的分解是否符合直觉

---

## 3. 第一批固定样例

## 3.1 高频同音与上下文依赖

### 样例 A1

```text
那时的我，总是刻意走在她的身后或身旁，心里装着一些说不出口的心事。
```

验证重点：

- `身后 / 神后`
- `身旁 / 神旁`
- 长句前文是否真的对后续词产生约束

关注现象：

- 若 `神后`、`神旁` 仍长期压过 `身后`、`身旁`，说明本地句级排序仍有明显结构性问题。

### 样例 A2

```text
年少的情感轻轻浅浅，不必言说，心里却澄澈得近乎透明。
```

验证重点：

- `澄澈 / 诚澈`
- 低频但合理的文学词语是否会被高频错误词压过

关注现象：

- 如果高频同音错词持续占优，说明语言模型分数仍然没有有效约束字典高频。

---

## 3.2 长句叙事表达

### 样例 B1

```text
忽然就觉得，秋天是有气息的，带着一点微凉，也带着一种不可挽回的流逝。
```

验证重点：

- 长句整体连贯性
- 标点存在时的上下文截取是否稳定

### 样例 B2

```text
我记得风吹过的时候，落叶在她发间轻轻停留，我却只能假装随意地看一眼，假装没有在意。
```

验证重点：

- 中长句中连续低频搭配是否能保持稳定
- 是否会出现高频单字拆散原本更合理的短词组合

### 样例 B3

```text
已经化作生命里最温柔的底色。
```

验证重点：

- 短句中抽象词组搭配
- 简短表达是否会被错误高频短词污染

---

## 3.3 新闻说明文风格

### 样例 C1

```text
反过来说，“什么样的休息不完整、不理想”，大家却总能达成共识。
```

验证重点：

- 规范表达中的稳定性
- 标点、引号与断句是否影响局部语言模型判断

### 样例 C2

```text
法定节假日、休息日、个人年假等一系列休息措施的落实，从制度层面不断拓展着公民的休息权。
```

验证重点：

- 长定语结构
- 高频公文/说明文分布下的排序稳定性

### 样例 C3

```text
真正优质的休息，不是对现实生活的“暂停”或逃避，而是一次深度的精神补给和自我对话。
```

验证重点：

- 抽象名词密集句的排序稳定性

---

## 3.4 文学与议论混合表达

### 样例 D1

```text
时间治愈的是愿意自渡的人。
```

验证重点：

- `自渡` 这类不算超高频但表达合理的词，是否会被错误高频词替换

### 样例 D2

```text
时间抹平年少懵懂的棱角，时间孕育岁月呕心沥血的产物。
```

验证重点：

- 连续抽象词与书面表达
- 语言模型是否能维持风格一致性

### 样例 D3

```text
打破时间束缚的牢笼，解开自我捆绑的绳索，让一切并然有序，自渡顺应生命的自然规律。
```

验证重点：

- 长句中的低频词和潜在错别字干扰
- 本地排序是否能暴露出“并然 / 井然”之类的潜在问题

---

## 4. 与主测试语料的关系

这份文档不是正式测试基线，而是：

- 从主测试语料中抽出的典型子集；
- 用于人工观察；
- 用于帮助开发阶段尽快定位典型错误。

因此：

1. 它适合“人工重点观察”；
2. 不适合作为任何正式通过标准；
3. 若主测试语料整体退化，即便这组样例没退化，也不能视为改动成功。

---

## 5. 当前阶段的观察重点

第一阶段不要求对所有样例都做到“最优文学判断”，但观察时至少应关注：

1. 高频明显错误词不应长期压过更合理的词组；
2. `Dict` 与 `LmScaled` 的贡献可以从日志中看清楚；
3. 同一版本重复测试时，排序结果应稳定；
4. 修改后能明确说出：
   - 哪些样例变好
   - 哪些样例退化
   - 退化由哪项分数引起

## 7. 当前建议

下一步建议基于这组样例做两件事：

1. 在全量测试之后，额外人工查看这组样例的输出；
2. 若全量结果出现退化，优先用这组样例辅助定位问题。

这样可以把“路线 B 的推进”从零散试句，变成“全量评测 + 典型观察”的工程过程。
